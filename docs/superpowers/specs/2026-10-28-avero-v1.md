# Avero V1 : ce qu'il faut pour un vrai client utilisable

Complète la spec de conception (`2026-10-27-avero-design.md`). Le plan 1 a posé
les fondations : comptes IMAP, synchro des en-têtes, boîte unifiée. La V1 en fait
un client mail utilisable au quotidien.

## Objectifs

1. **Ajout de compte facile.** L'utilisateur tape son adresse et Avero trouve
   les serveurs tout seul. Pour Gmail et Outlook, il clique sur « Continuer avec
   Google/Microsoft », le navigateur s'ouvre et l'autorisation revient seule
   dans l'application (OAuth2, redirection loopback, PKCE).
2. **Lire** : corps du mail (texte, ou HTML converti en texte, sans contenu
   distant), pièces jointes enregistrables, marquage lu automatique.
3. **Agir** : répondre, répondre à tous, transférer, écrire un nouveau mail
   (SMTP), archiver, supprimer (corbeille), marquer lu/non lu.
4. **Naviguer** : dossiers unifiés (Réception, Envoyés, Brouillons, Archives,
   Spam, Corbeille), filtre par compte, recherche locale (FTS5).
5. **Rester à jour** : la boîte de réception est synchronisée en premier, la
   liste se rafraîchit pendant la synchro, synchro automatique toutes les
   5 minutes, bouton actualiser, drapeaux et suppressions de la boîte de
   réception resynchronisés.
6. **Gérer les comptes** : renommer, changer le mot de passe, se reconnecter
   (OAuth), supprimer.
7. **Design moderne** propre à Avero (voir « Direction visuelle »).

Hors V1 (inchangé) : tri intelligent, anti-spam, grand nettoyage, snooze et
désinscription en un clic restent dans les plans 5 et 6.

## Règles de sécurité (inchangées et étendues)

- Les secrets (mots de passe, jetons de rafraîchissement OAuth) vont uniquement
  dans `SecretStore`. Les jetons d'accès restent en mémoire.
- Les secrets n'apparaissent jamais dans un message d'erreur, un log ou une
  sortie `Debug`. Les types qui portent un secret implémentent `Debug` à la main
  et affichent `***`.
- IMAP uniquement en TLS implicite. SMTP en TLS implicite (465) ou en STARTTLS
  obligatoire (587), jamais en clair.
- Le contenu des mails ne part que vers les serveurs du compte. La détection
  automatique envoie seulement le **nom de domaine** à
  `autoconfig.thunderbird.net` et à `autoconfig.<domaine>`.
- Aucun contenu distant n'est chargé (images, CSS) : le HTML est converti en
  texte.
- Les identifiants client OAuth ne sont pas des secrets (application de bureau,
  « installed app »). Ils sont lus à la compilation
  (`AVERO_GOOGLE_CLIENT_ID`, `AVERO_GOOGLE_CLIENT_SECRET`,
  `AVERO_MICROSOFT_CLIENT_ID`) ou au lancement depuis `oauth.json` dans le
  dossier de configuration. Sans identifiant configuré, le bouton correspondant
  indique pourquoi il est indisponible, et le mot de passe d'application reste
  possible pour Gmail.

## Découpage en crates

| Crate | Rôle | Dépend de |
|---|---|---|
| `avero-core` | modèle, base SQLite, secrets | — |
| `avero-autoconfig` | (nouveau) adresse → serveurs | — |
| `avero-oauth` | (nouveau) flux OAuth2 loopback, rafraîchissement | — |
| `avero-sync` | IMAP (lecture, drapeaux, déplacements), SMTP, analyse MIME | core |
| `avero-app` | interface iced | tous |

```rust
pub struct ServerConfig { host, port: u16, username, security: Security }
pub enum AuthKind { Password, OAuthGoogle, OAuthMicrosoft } // "password" / "oauth-google" / "oauth-microsoft"

```

### avero-autoconfig

```rust
pub enum OAuthProvider { Google, Microsoft }
pub enum AuthMethod { Password, OAuth(OAuthProvider) }
pub struct Server { host: String, port: u16, security: Security /* avero_autoconfig::Security */, username: UsernameKind }
pub enum UsernameKind { Email, LocalPart }
pub struct ProviderConfig {
    display_name: String,          // "Gmail", "Outlook.com", "Orange"…
    imap: Server, smtp: Server,
    auth: Vec<AuthMethod>,         // méthodes possibles, préférée en premier
    password_help: Option<PasswordHelp>,

pub struct PasswordHelp { text: String /* en français */, url: String }
pub fn known(email: &str) -> Option<ProviderConfig>;            // table intégrée, sans réseau
```


### avero-sync

- `ImapSource::connect(cfg: &ServerConfig, creds: &Credentials)` : LOGIN ou
  AUTHENTICATE XOAUTH2.
- `MailSource` gagne `fetch_flags(uids)`, `fetch_body(uid)`,
  `set_seen(uids, bool)`, `move_to(uids, dest_path)` (MOVE si annoncé, sinon
  COPY + \Deleted + EXPUNGE), `append(path, raw, seen)`.
- `sync_account(store, source, account, on_progress: impl FnMut(&SyncReport))` :
  INBOX en premier, ignore les dossiers `\All`, `\Flagged`, `\Important`
  (doublons Gmail), resynchronise drapeaux et suppressions de la boîte de
  réception.
- `parse::parse_body(raw: &[u8]) -> ParsedBody { from, to, cc, reply_to, date, subject, message_id, references, text: String, attachments: Vec<Attachment{ name, mime, size, index }> }`,
  où le texte vient de text/plain, sinon du HTML converti en texte.
- `smtp::send(cfg: &ServerConfig, creds: &Credentials, msg: &Outgoing) -> Result<Vec<u8> /* message brut envoyé */, SendError>`
  avec `Outgoing { from_name, from_addr, to, cc, bcc: Vec<String>, subject, body, in_reply_to, references: Option<String>, attachments: Vec<OutgoingAttachment{ name, mime, data }> }`.

## Direction visuelle

Le nom évoque l'oiseau (*avis*) et le vrai (*vero*) : de la légèreté, de l'air
et de la clarté. L'interface est calme, aérée et sans fioritures, avec un seul
accent vif.

- **Couleurs (clair)** :
  - fond papier `#F6F5F2`, surface `#FFFFFF`, surface secondaire `#EFEDE8`, bordure `#E4E1DA` ;
  - texte `#1C1B22`, texte discret `#6B6875` ;
  - accent « plume » `#5B4FE8`, accent doux `#ECEAFD` ;
  - danger `#E5484D`, succès `#30A46C`.
- **Couleurs (sombre)** :
  - fond `#121118`, surface `#1A1922`, surface secondaire `#23222D`, bordure `#2E2C3A` ;
  - texte `#ECEAF4`, texte discret `#9A97A8` ;
  - accent `#8B80FF`, accent doux `#2A2650`.
- **Thème** : il suit le système, ou est choisi dans les réglages.
- **Barre latérale (rail)** : 64 px, couleur encre (`#1C1B22` en clair, `#0C0B10` en sombre). Le logo est en haut. Les icônes sont vectorielles (SVG Lucide, licence ISC) et remplacent les glyphes Unicode.
- **Logo** : une aile ou un « A » en chevron stylisé, dans l'accent. Il sert aussi d'icône de fenêtre.
- **Typographie** : Inter (OFL) embarquée. Titres en demi-gras, texte en 14 px, métadonnées en 12 px.
- **Formes** : rayons de 10 px pour les cartes, 8 px pour les boutons et champs. Bordures fines, pas d'ombres lourdes.
- **Liste** : avatar rond avec l'initiale, en couleur du compte. Expéditeur en gras si non lu, objet, extrait d'une ligne, date à droite et point d'accent si non lu.
- **Accueil (aucun compte)** : logo, phrase d'accroche, gros boutons « Continuer avec Google » et « Continuer avec Microsoft », puis « Autre adresse e-mail ».
